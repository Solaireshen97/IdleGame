# T1 装备设计与实现进度

目标：完成整个T1阶段的装备设计与实现，以每天12小时、首周约84小时形成可玩装备为数值目标。第一版实现与验收已完成，详见 [发布说明](t1-release-notes.md)。

## 用户约束

- 每阶段完成后检查账户额度；任何可见额度窗口接近剩余 20% 时保存进度并停止推进，给用户保留余量。
- 各阶段结束额度：第一阶段剩44%，第二阶段43%，第三阶段42%，第四阶段40%，最终38%；接口只提供周窗口。
- 不改动用户运行中的数据库；通过迁移和临时数据库验证兼容性。

## 阶段与验收

1. **武器技能基础（已完成代码与自动验证）**：八效果、四复合技能、按效果合计递减、战斗触发边界、武器盘与商店描述、数据库迁移；构建通过，194 项测试通过（含 22 项新增效果与迁移验证）。页面视觉检查纳入最终验收。
2. **完整 T1 武器内容（已配置并自动验证）**：24 普通武器、6 Boss、36 普通兑换、12 精英、7 阶段末武器；新增 Lv.10 深层矿洞、六元素兑换及独立徽记。旧实例通过版本迁移保留元素、栏位、锁定、品质与强化，挂起奖励也升级模板。201 项测试通过；怪物数值仍待阶段四校准。
3. **获取与养成经济（已完成代码与自动验证）**：新账号120金币、六属性商店武器40金币、强化2/8/24、按实际投入返还50%、按装备来源限制回收；新手首次普通讨伐额外白装写入奖励账本，账号内跨角色仅一次；普通副本12徽记、深层18徽记。205项测试通过，客户端与服务端构建成功。
4. **实际战斗与节奏校准（已完成本轮）**：技能倍率与按最大生命回复接入后端，普通/正式/精英/深层怪物已调整。208项测试通过；870场真实服务端模拟，另有每职业/元素2000次资源抽样。固定资源投影不等于新账号84小时全程挂机验证。
5. **完整验收（已完成）**：构建、208项测试、临时旧库迁移、桌面及390像素窄屏、隔离HTTP获取与回收流程均通过；设计及运行说明已更新。测试端口已关闭，用户游戏数据库未直接修改。

完整实现及验收依据见 `t1-release-notes.md`，数值设计依据见 `t1-progression-balance.md`。

## 阶段四处理记录与验证边界

- 普通/正式副本原几十到几百生命不足以承受新装备，已按真实战斗调整怪物生命/攻击/防御，修正了预览与实际遭遇数值不同步的风险。
- 职业伤害现在支持攻击倍率+固定威力；治疗和药水支持最大生命百分比。T1CombatScalingTests验证真实回合、回复量及药水预览。
- 普通攻击后才结算职业技能与消耗品，击杀后跳过这些行动；敌人之间只有3秒切换、自动回合间隔30秒、重开等待30秒。模拟必须使用完整流程，不能把每名敌人都计作固定30秒。
- `t1-combat-final.json`记录720场成型配装，entry记录120场起步，party记录30场五人队。每场景5个种子，仅报告样本结果，不当作长期胜率保证。
- `t1-economy-projection.json`记录固定82小时刷取+2小时探索预算的资源充足性；未动态模拟新账号逐步换装，不能证明玩家必须花满或保证在84小时通关。
- 当前没有人数缩放；单角色与五角色队伍已分别报告。水属性对土属性深层首领明显不利，需要调整配装/技能或组队，不能宣称固定配装适用于所有敌人。
