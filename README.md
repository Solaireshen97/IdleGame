# IdleGame V1.0

基于 .NET 10 LTS、ASP.NET Core Web API、Blazor WebAssembly、EF Core 和 SQLite 的网页放置类战斗游戏骨架。

## 项目结构

- `Game.Shared`：共享模型、枚举和 DTO
- `Game.Server`：Web API、SQLite 持久化及领域服务
- `Game.Client`：Blazor WebAssembly 客户端
- `Game.Server.Tests`：服务层测试

单机存档备份、恢复和发布流程见 [单机内测运维](docs/single-host-operations.md)，架构优化进度见 [实施记录](docs/server-architecture-plan.md)。`/liveness` 检查进程存活，`/readiness`（或 `/health`）同时检查数据库和房间、生产后台扫描。

当前四块药田、并行炼金、普通/次级/强效药剂与测试配表见 [并行种植与炼金实施稿](docs/planting-alchemy-redesign.md)。

## 角色状态与一致性边界

- `CharacterLifecycleService` 负责创建、选择、删除及角色数据清理。三类操作共同校验账号版本；删除检查与提交处于同一事务，至少保留一个角色。首猎领取记录、残留药剂效果随角色清理，已记录的奖励历史继续保留。
- `CharacterAccessResolver` 只解析当前角色与归属，不保存数据。旧存档的当前角色为空或失效时，读取回退至首个自有角色；明确选择或删除操作负责保存有效选择。读取角色不会顺带提交其他尚未保存的改动。
- 创建房间、加入房间和房主编入角色都校验角色版本，与切职业、换装共享并发保护。种植和炼金继续允许与战斗并行；角色的当前选择与其在房间内的操作身份分别处理。
- 装备基础属性统一通过 `CharacterEquipmentStats` 计算，初始化、换装和装备模板更新复用同一入口；满血或裁剪 HP 仍由各操作决定。战斗数值使用不可变的 `CharacterCombatStatSnapshot`，当前 HP 与回合数保持实时，原伤害乘区、上限与取整规则保持一致。旧临时字段与旧生活职业字段暂作兼容入口保留。
- `CombatProfessionProgressStore` 统一奖励和切职业的进度同步：当前职业仍以 `Character` 为准，职业表保存镜像和非当前职业进度。技能栏写入带版本的快照，兼容旧数组；损坏内容按现行技能规则恢复，未知版本拒绝覆盖。数据库表结构保持兼容。
- 客户端 `CharacterContextCoordinator` 统一角色摘要、账号摘要和角色金币的读取协调。账号切换拒绝旧账号响应；同账号切换角色只使依赖当前选择的请求失效，明确指定房间或角色的战斗命令仍按其原操作对象接收结果。缓存合并与归属校验继续保留。

## V1.0：副本、首通、准备超时与 Auto

每个房间固定包含 5 个战斗槽位。创建者可在非战斗阶段编入多个自有角色；其他玩家可将自己的当前激活角色加入一个空槽位，每名外来玩家最多占用一个槽位。

- 槽位 1～5 决定行动顺序；角色按升序依次攻击。
- 怪物攻击存活角色中槽位编号最小者。
- 每个角色只能占用一个房间的一个槽位。
- 房主可在首回合前或战斗结束后，在空位选择已上阵的自有角色直接移入，或在自有队员的位置选择另一名已上阵角色交换站位；待执行指令与参战记录随角色移动，不恢复 HP，不改变参战人数，也不能移动其他玩家的队员。
- 房间有空槽时，外来玩家可在未开始、准备中、回合冷却、波次切换以及重复战斗的胜利等待期间中途加入；加入准备阶段会重新给队伍完整的准备倒计时。房主自己的队伍编成仍只在首回合前或战斗结束后调整。
- 组队操作可提前提交。允许操作时立即执行；暂时锁定的上阵、移除、移动、交换站位和退出会保存为预约，在本场战斗结束后、下一场开始前由服务端执行，关闭页面也不影响。队伍面板可查看状态并取消；独立位置的预约可并存，新提交的冲突选择会替换旧预约。执行前重新检查角色归属、等级、活动占用和位置，条件改变时显示失败原因，不覆盖新队员。加入目前在上述阶段已允许，继续立即执行，不额外等待。
- 每名玩家独立点击“准备”，全体存活角色确认后立即结算回合。冷却中可提前准备；尚未结算时可点“取消准备”，只撤回自己的手动角色确认，保留已排队技能、魂印、道具及原倒计时。请求校验场次和回合，旧请求不能影响重复战斗的新一场。
- 房间基于副本创建，默认提供史莱姆平原、哥布林营地和狼群森林；`DungeonEncounters` 配置段定义每个副本的波次及每波怪物顺序，每个房间保存一套独立怪物实例。
- 史莱姆平原当前用于验证三波流程；哥布林营地和狼群森林暂时保持单波。击杀一只怪物后等待 3 秒切换下一只，最后一只怪物死亡才算通关并记录首通。
- 波次之间保留角色 HP、技能冷却、道具冷却和当前回合数。下一只怪物不会在被切换出来的同一回合反击。
- 一个 Auto 开关统一控制自己在房间中的全部角色，不影响其他玩家；每名角色仍需自己通关当前副本才会自动准备、自动施放职业技能或魂印，未通关角色继续手动准备。房主副角色跟随这个开关，关闭时撤回自己的准备确认并保留手动排队。准备超时与离线都不会替玩家打开 Auto。
- 创建房间时可选择 60 秒准备超时。战斗页每 2 秒发送一次在线心跳；角色超过 30 秒未被服务器看到会显示为离线。准备超时只会让未准备角色执行本回合普通攻击，不会替角色启用 Auto 或自动释放技能。全队都处于 Auto 时，服务器每 20 秒自动推进一回合；有人返回手动操作后恢复 10 秒手动回合间隔。
- 最终怪物死亡或全队死亡后，房间进入 `BattleOver`。
- 战斗结束后，仅房主可手动重置房间；重置会恢复所有波次怪物及全队角色的 HP，并清除技能和道具冷却。重复战斗胜利后的等待阶段由服务端自动重开，不能手动跳过。
- 创建房间时可选择单次或重复战斗。重复模式在胜利 30 秒后由服务端重开副本，恢复怪物及队伍角色的全部 HP；战败后停止。
- 重开后的每个回合仍遵守现有的准备与 Auto 规则。服务端定时推进超时、离线 Auto 和重复重开，所有房间页关闭后也能继续；在线且未启用 Auto 的角色仍需手动准备。
- 双方仍存活时，进入 10 秒 `Cooldown`。
- 房间版本号是 EF Core 并发令牌，确保并发回合最多一个结算成功。

队伍不再设置主控角色。创建／加入房间使用账号当前选择的角色，战斗页默认操作该角色，仍可直接点击其他自有队员的技能。房主可以移除任意自有队员，再把其他角色放到空位；房主权限始终属于账号。

战斗界面的“快速释放”按角色保存在账号中，切换队员、重新进入房间或换设备后会恢复该角色的设置。新角色默认关闭；修改此偏好不会改变战斗准备、Auto、生命值或当前活动。

Auto 开关在每个房间内按账号控制自有队员；房主的设置独立保存在房间中，切换当前角色、调整站位、角色死亡或移除队员不会改变开关。新编入的自有队员跟随该设置，但仍需自己通关副本才会实际自动准备、自动施放技能或魂印；外来玩家的设置互不影响。升级旧存档时会保留原开关状态。

## 讨伐人数与怪物生命

- 每项战斗内容通过 `World.Dungeons[].PartyScalingProfileCode` 显式选择强度方案，不按怪物数量、波次数或是否首领判断。普通讨伐与精英讨伐使用 `hunt-hp`，普通副本、精英副本与旧隐藏内容使用 `fixed`；单怪团队副本同样可配置为 `fixed`。
- `PartyScaling.Profiles` 集中配置 1～5 个角色的 HP 百分比。当前讨伐为 `100 / 180 / 260 / 340 / 420%`，只增加生命，攻击、防御及奖励沿用原配置。同账号的多个上阵角色分别计数。
- 首回合结算前按实际阵容计算；开战后只上调本场已采用的人数。中途加入按新旧最大 HP 比例调整当前 HP，保留剩余血量百分比，整数结果向上取整。例如 `1000 / 10000` 在第二人加入后变为 `1800 / 18000`。
- 阵亡、离线不降低本场怪物生命；战斗中离队及移除角色仍遵守现有阶段限制。胜利等待期间的加入和离队只影响下一场，不会复活已击败怪物。
- 怪物实例保存基础最大 HP；手动重开和自动重复战斗均从基础数值按最新阵容计算，避免倍率叠乘或沿用上一场人数。
- 全自动重复战斗在击杀后 5 秒刷新，再等待约 15 秒进行下一场首回合；这两段合计 20 秒。每小时收益应按完整循环测算，不能把刷新时间当作下一场已经开始输出。
- 讨伐人数倍率不改变经验和独立掉落；战斗职业经验现按原奖励全额发放，满 30 级后停止获得经验。本次生命倍率仍待实际刷取体验验证。

## 战斗消耗品

- 背包和两个战斗补给槽均属于角色。不同角色的库存、装备及自动使用设置相互独立；只有角色本人能读取或修改。
- `Consumables` 配置段定义道具效果、冷却组和冷却回合数。当前示例为小型治疗药水：回复 20 HP、治疗组冷却 3 回合。副本奖励统一在 `Rewards` 配置段调整。
- 手动选择补给槽会把指令排入下一次战斗结算，不会立即扣库存或回复 HP；传入空槽号可取消。每名角色每回合最多使用一个道具，使用道具不取代攻击。角色攻击和技能结算后若怪物仍存活，先使用道具，再承受怪物攻击；战斗已胜利时不消耗道具。战前调整已排队的补给槽会取消该指令。
- 自动使用与角色的 Auto 准备独立。装备时可选择是否自动使用及 HP 百分比阈值；手动使用可越过自动阈值，但仍需角色存活、HP 未满、库存充足且冷却结束。
- 同一冷却组的道具共享冷却。第 0 回合使用冷却 3 回合的道具后，第 1～3 回合不可使用，第 4 回合恢复可用。手动重置或重复战斗重开会清除该房间的冷却，不会补回已消耗的库存。
- 房间详情只向角色所属玩家返回该角色的补给槽、库存和剩余冷却；所有使用条件和库存扣减由服务端验证并执行。
- 左侧导航的“战斗补给”页面可查看当前操作角色的库存、装备道具和设置自动使用阈值。战斗房间的“行动指令”区可为自己的上阵角色手动排队或取消使用，并显示库存及剩余冷却。

## 战斗职业与技能系统

当前角色与怪物技能架构、配置示例及重构验收见 [角色与怪物技能系统](docs/skill-system-refactor.md)。

- 五个战斗职业为骑士、祭司、法师、猎人、盗贼，各有五个本职技能，职业等级上限 30。骑士沿用 `swordsman` 配置代码。技能在 1／3／5／7／10 级解锁，12／14／16／18／20 级升级至 Lv2，22／24／26／28／30 级升级至 Lv3。
- 角色可在职业界面切换职业，各职业独立保存等级、经验和五栏技能编成。技能自动随职业等级学习；旧战斗天赋树和进阶转职入口已退休。种植与炼金遵循各自的资源和配方规则。
- 一个来源职业满 30 级后解锁指定共享技能；当前职业达到 10 级才可装备，最多装备一个共享技能。共享版本有独立效果和冷却，不能当作完整本职 Lv3 使用。
- 技能定义、版本、目标与 Auto 条件在服务端编译并校验。手动指令先按角色站位及技能栏顺序执行，然后处理合资格 Auto 技能；同技能一回合最多施放一次，均不替代普通攻击。
- 回合顺序为作战药剂与武器增益、魂印、职业技能与触发、普通攻击与追击、治疗药水、怪物行动及反击、周期效果与状态清理。普通守护当回合生效，同一目标保留较强项，减伤上限 75%；反击归实际保护者。
- 初始冷却为开始可用前的轮数；成功施放后就绪轮次为当前轮次加常规冷却再加 1。状态持续 N 回合包含施加当轮及其后的 N 轮，周期伤害和恢复首次从后续轮结算；仅当轮效果明确使用当前回合生命周期。
- 职业资源、强化次数、来源、绑定目标及强度都由正式状态保存。角色自身机制显示在角色 Buff 栏，敌方承受的效果显示在怪物栏。波次切换清理旧目标绑定的状态；允许跨波的角色状态保留，挑战胜利、战败、重开或关闭时清空。
- 技能详情和怪物预告直接使用统一定义生成的效果说明。伤害、治疗、打断、冷却及 Buff 添加／刷新／消费／移除使用保存成功后的结构化事件播放，角色和怪物按编号定位。中文战报仅用于阅读。
- 存档中的旧战斗天赋节点保留兼容效果，集中在 `LegacyBattleTalentService` 和两个兼容适配器；新职业系统不会发放旧节点。旧追击同样使用正式状态及事件，旧节点数据不影响当前按等级学习和共享技能的资格。

## 武器编成与被动技能

当前三档技能与过渡武器数值见 [武器技能三档设计](docs/weapon-tier-balance.md)。首批六属性十二把深层三词条武器已配置面板和技能，获取入口待副本设计会话接入，见 [T1 首批深层武器](docs/t1-deep-weapons-design.md)。

- 每名角色拥有独立的武器背包和十个栏位：1 个主武器、9 个副武器。主武器决定角色属性；同一件武器不能占两个栏位，从另一个栏位选择武器时会交换位置。
- 十个已装备栏位的武器攻击和最大 HP 均相加，不按属性筛选。角色的攻击与最大 HP 字段保存这个基础总和；天赋固定加成和武器技能加成在结算时加入。换装不会恢复当前 HP；最大 HP 降低时会裁剪当前 HP。
- 每把武器最多带 3 个被动技能，技能定义与各武器等级位于 `Weapons` 配置段。只有与主武器同属性的已装备武器贡献技能；同名技能等级相加，例如三把攻击 Lv 2 合计 Lv 6。不同属性的武器仍贡献基础攻击和 HP。
- 技能分小／中／大档，线性按等级成长。攻击每级 +1.5%／2.5%／4%，生命每级 +2%／3%／4.5%，暴击率每级 +1%／1.5%／2%；各效果合并后受独立上限约束。暴击由服务端对每次普通攻击或伤害技能单独判定，触发时进入独立的 150% 暴击伤害乘区；完整效果表见上述技能设计文档。
- 新角色直接装备十把对应职业初始属性的商店武器，每把攻击 90、生命 110、生命小 Lv1。每把武器归角色本人，只有所属玩家能查看和操作；技能均从 Lv1 开始，突破阶级 0／1／2／3 时上限为 Lv4／Lv6／Lv8／Lv10。服务启动时会按当前技能配置重新汇总角色的装备加成。
- 武器盘页面展示主武器、3×3 副武器、每把武器的技能等级及当前生效技能。战斗进行期间锁定换装，主武器不能被直接卸空。击杀掉落的武器进入所属角色的武器背包，不会自动装备。

## 统一奖励与掉落池

- 六属性深层本已改用各自两把新武器：前四怪每把各 1%、Boss 各 5%，独立判定；普通通关固定 5 枚 T1 武器碎片、1 枚本副本徽记，魂印 1%，武器定向兑换为 60 枚徽记。已替换旧武器获取池；已有装备与冻结房间仍兼容。养成口径与编号见 [首批深层武器](docs/t1-deep-weapons-design.md)。约一天毕业一把以 30 分钟一局为前提，当前六属性LV1～LV4已完成战斗时长校准，LV5～LV10挑战规则已接入，未逐层战斗标定。
- `Rewards.MonsterKills` 和 `Rewards.DungeonClears` 分别配置击杀奖励与通关奖励，每项可设金币、经验和按概率独立判定的道具或武器。每只怪物死亡时按波次和序号把击杀奖励加入本轮奖励池；最终一波完成时再加入一次通关奖励。
- 服务端以房间轮次和事件键保存已判定的奖励；随机掉落结果与武器数值、技能快照在入池时固定。胜利时追加通关奖励并结算；全队战败时仅结算此前入池的奖励。金币、经验、消耗品和武器均归具体参战角色。
- 奖励池、金币、经验、物品、武器和房间结果在同一次数据库提交中保存。重复战斗的每次重开使用新轮次；事件唯一键与房间并发版本共同避免重复发奖。战斗房间的战利品面板累计显示当前房间所有轮次属于自己的收益，按角色切换并合并同类物品；本轮入池但未结算的奖励会单独标注，经验以结算时为准。房间结束后保留相同的角色分组，顶栏显示当前操作角色的金币。

## 商店

- 左侧导航的“商店”页面展示当前角色金币、当前操作角色、商品价格和角色已拥有数量。消耗品可一次购买 1、5 或 10 件；武器一次购买一件，直接进入该角色的武器背包且不会自动装备。
- 商品与价格在 `Shop.Items` 配置段维护。首批商品包括小型治疗药水和六种属性的基础武器；商品的效果与属性继续由 `Consumables` 和 `Weapons` 定义。
- 购买请求只提交角色、商品代码和数量。后端核对当前角色、配置价格、余额与库存上限，并在同一次数据库提交中扣除当前角色金币、增加角色库存。角色版本与道具库存版本用于拒绝并发重复扣款。

## 属性克制与伤害结算

- 角色属性由主武器决定；副武器的属性不影响克制。未装备主武器的旧测试角色按无属性结算。副本模板决定怪物属性，新房间复制该属性；旧房间在迁移时按所属副本补齐。
- 火克风、风克土、土克水、水克火。克制方造成 125% 伤害，被克制方造成 75%；同属性及其他无克制组合为 100%。光暗相遇时玩家固定占优：玩家造成 125%，怪物造成 75%。
- 普通攻击、伤害技能和怪物反击共用后端计算器：`max(1, floor(max(1, (攻击 + 技能固定威力) × 攻击乘区 − 防御) × HP 状态乘区 × 暴击乘区 × 属性乘区 × 减伤乘区))`。每个乘区内部的百分比增减先相加，乘区之间相乘，最后统一向下取整。武器攻击技能进入攻击乘区，暴击触发时进入暴击乘区，守护技能进入减伤乘区；HP 状态乘区留给后续强壮和背水等效果。

## 怪物技能与状态效果

- 怪物每回合只计划一个行动。服务端会在回合开始时一次性确定普通攻击或技能、目标和技能冷却，并保存为本回合意图；读取房间详情不会重新随机。战斗界面会在玩家准备前展示技能名称、效果、危险等级、目标及是否可打断。
- 怪物技能在角色的普通攻击、职业技能和消耗品之后结算。预告的单体目标在结算前死亡时，本次行动失去目标并取消；全体技能会命中结算时仍存活的角色。
- `MonsterCombat` 配置段定义状态、技能和技能组。怪物技能可使用有顺序的 `Effects` 组合伤害、自疗、守护、净化、驱散和状态附加；旧 `DamagePowerPercent`／`Statuses` 配置继续编译到同一执行器，不能与 `Effects` 混用。`DungeonEncounters` 中怪物的 `CombatProfileCode` 决定其技能组；技能组可设置每回合使用技能的概率及多个技能的选择权重，技能自身可配置目标、伤害倍率、冷却、生命条件、房间回合条件、强制优先级和附加状态。
- 角色与怪物共用状态服务，支持属性增减、周期伤害与治疗、资源层数、消费次数和职业机制；来源、目标绑定、数值快照及生命周期持久化。切换怪物清理旧怪物及其绑定资源，挑战结束与重开清空当前挑战状态。
- 状态可独立配置是否允许净化或驱散。被打断的怪物技能仍会进入自身冷却；标记为不可打断的技能不会被手动或 Auto 打断，史莱姆王的剧毒爆发是首个不可打断技能。
- 六个 Lv.10 终局副本的首领从第 22 回合起进入周期性全体软狂暴，第 42 回合后进入反复硬狂暴；强制阶段技能会越过普通技能概率，但仍生成并持久化战斗预告。详细人数与 Auto 边界见 `docs/t1-endgame-acceptance.md`。
- 史莱姆平原第二波用于验证腐蚀喷射与黏液硬化，最终波的史莱姆王用于验证全体中毒和低生命攻击强化。第一波仍使用普通攻击，方便对比基础战斗流程。

## API

六个初始地区、正式副本、特色武器与徽记兑换的设计及配置说明见 [初始地区文档](docs/starter-regions.md)。

- `GET /api/regions`：获取地区介绍、等级范围、特色副本和专属武器；大厅按地区切换挑战。
- `GET /api/dungeons`、`GET /api/dungeons/{dungeonId}`：获取副本配置及当前用户首通和 Auto 解锁状态。
- `GET /api/shop`：读取当前角色的商品列表、持有数量和金币。
- `POST /api/shop/purchase`：为当前角色购买商品，请求体为 `characterId`、`code`、`quantity`；价格由服务端读取。
- `POST /api/rooms`：使用 `dungeonId` 和可选的 `isRepeatBattle` 创建房间，并按副本容量初始化槽位；旧 `monsterType` 请求仍兼容，默认单次战斗。
- `GET /api/rooms/{roomId}`：获取房间版本、怪物编号、状态、预告、完整槽位信息、阅读战报及结构化战斗事件。
- `POST /api/rooms/{roomId}/slots`：上阵自有角色，或移动／交换已上阵自有角色。请求体为 `slotIndex`、`characterId`。
- `DELETE /api/rooms/{roomId}/slots/{slotIndex}`：移除自有槽位角色。
- `POST /api/rooms/{roomId}/join`：使用当前激活角色加入指定空槽位。请求体为 `slotIndex`。
- `DELETE /api/rooms/{roomId}/leave`：外来玩家离开自己的槽位。
- `POST /api/rooms/{roomId}/operations`：立即执行或预约组队操作。请求体为 `kind`（0 加入、1 退出、2 上阵/移动/交换、3 移除）、`slotIndex`，上阵时另传 `characterId`。账号身份由登录会话确定，加入使用提交时选定的角色；响应房间的 `operations` 仅包含本人操作。
- `GET /api/rooms/{roomId}/operations`：读取本人的预约与执行结果，退出私人房间后仍能读取本人结果。
- `DELETE /api/rooms/{roomId}/operations/{operationId}`：取消本人的待执行预约；已经结束的预约不能取消。原加入、退出及槽位接口保留立即操作的阶段限制，游戏 UI 使用预约接口。
- `POST /api/rooms/{roomId}/slots/{slotIndex}/auto`：设置自己的永久 Auto。请求体为 `isAutoEnabled`。
- `POST /api/rooms/{roomId}/preparation-timeout`：房主设置纯自建队的准备超时偏好。请求体为 `isEnabled`。
- `POST /api/battle/prepare`：确认当前用户的存活角色；全员确认后自动结算。请求携带 `roomId`、`expectedRunSequence`、`expectedRoundNumber`。
- `POST /api/battle/cancel-prepare`：撤回本人手动角色的准备确认；同样必须携带房间、场次、回合，重复取消幂等。
- `POST /api/battle/sync`：推进准备超时及全员 Auto 回合。
- `POST /api/battle/reset`：房主在战斗结束后手动重置；战斗进行中或重复战斗胜利等待期间会拒绝请求。
- `GET /api/user/characters/{characterId}/consumables`：读取自有角色的背包数量、道具定义和两个补给槽。
- `GET /api/user/characters/{characterId}/weapons`：读取角色独立武器背包、十槽编成、主属性与合计属性。
- `PUT /api/user/characters/{characterId}/weapons/slots/{slotIndex}`：设置 1～10 号武器栏位，请求体为 `weaponId`；副位可传 `null` 卸下，主位不可为空。已装备的武器会与目标位交换。
- `PUT /api/user/characters/{characterId}/consumables/{slotIndex}`：设置补给槽，`slotIndex` 为 1 或 2；请求体为 `itemCode`（可为 `null`）、`autoUseEnabled`、`autoHpThresholdPercent`（1～100）。战斗进行时不能调整装备。
- `POST /api/battle/consumable`：排队或取消下一回合的手动道具使用；请求体为 `roomId`、`characterId`、`consumableSlotIndex`（1、2 或 `null`）。成功后返回房间详情。
- `GET /api/skills/professions`：获取可创建的职业。
- `GET /api/skills/professions/{characterId}`、`POST /api/skills/professions/{characterId}/switch`：读取职业等级、共享解锁与切换职业，切换请求包含 `professionCode`。
- `GET /api/user/characters/{characterId}/skills`、`PUT /api/user/characters/{characterId}/skills/{slotIndex}`：读取和设置自有角色的技能栏、自动使用条件。
- `POST /api/user/characters/{characterId}/skills/swap`：交换两个技能栏位及其自动设置。
- `GET /api/planting`、`POST /api/planting/plant`、`POST /api/planting/harvest`：查看四块药田、播种和收获；播种请求含唯一 `requestId`，地块操作携带当前版本。
- `POST /api/production/start`：战斗期间也可炼金；请求含 `characterId`、`recipeCode`、唯一 `requestId` 及可选 `targetCycles`（1–4320批），省略批数时最多连续12小时。
- `POST /api/shop/purchase`：购买次级药、普通种子或武器；请求含唯一 `requestId`，重复请求不重复扣款。
- 旧 `api/gathering` 与 `api/professions` 生活专业接口返回410；种植与炼金不再使用生活经验和天赋。
- `POST /api/battle/skill`：手动排队或取消一个技能栏位；请求体为 `roomId`、`characterId`、`skillSlotIndex`、`isQueued`。

## 本地运行

需要 .NET 10 SDK；仓库的 `global.json` 选择已安装的最新 .NET 10 SDK 功能带并排除预览版。客户端发布需要 `wasm-tools` 工作负载。框架依赖的服务端部署需要 ASP.NET Core Runtime 10，独立维护工具需要 .NET Runtime 10。

```bash
dotnet restore IdleGame.sln
dotnet build IdleGame.sln
dotnet run --project Game.Server/Game.Server.csproj
dotnet run --project Game.Client/Game.Client.csproj
```
